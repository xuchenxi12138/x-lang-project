# X-OS 运行说明

内核用 X 语言写（`kernel/src/kmain.xle`），汇编只出现在引导扇区与入口桩。

---

## 一、两种跑法，先看能力对比

| | 宿主仿真档 | 真镜像（QEMU / 真机） |
|---|---|---|
| 命令 | `sh tools/run-emu.sh` | `sh tools/build.sh` 后启动 `xos.img` |
| 启动耗时 | 立即 | 需 QEMU 或写盘 |
| VGA 排版 / 滚动 / 光标 | ✅ 真实逻辑 | ✅ |
| 串口输出 / UTF-8 编码 | ✅ 真实逻辑 | ✅ |
| shell 命令解析 | ✅ 真实逻辑 | ✅ |
| 自检、内存探测 | ✅ 真实逻辑 | ✅ |
| 中断（IDT/PIC）、分页 | ❌ 未覆盖 | ⚠️ 尚未实现 |
| GDT / 特权级切换 | ❌ 未覆盖 | ✅ |
| 真实 I/O 时序、地址解码 | ❌ 未覆盖 | ✅ |

**仿真档是开发期工具，不是验收替代品。** 它把「读写物理地址 / I/O 端口」换成内存里的假硬件，其余全部是真代码——同一份 `kmain.xle`，同一个编译器，没有第二套实现。

## 二、宿主仿真档（先在 PC 上跑起来）

```sh
cd x-os
sh tools/run-emu.sh
```

你会看到（节选）：

```
X-OS booting...

  +--------------------------------------+
  |           X-OS  kernel 0.1.0         |
  |        written in the X language     |
  +--------------------------------------+

boot params: ok
memory: ~127 MB detected
kernel heap base: 0x00100000

running self-check:
  [ok] memory write/read 32-bit
  [ok] memory 8/16-bit width
  [ok] serial loopback
  [ok] string interpolation
  [ok] array push (100 elements)

  all 5 checks passed

kernel initialized. entering shell.

x-os> help
commands:
  help      show this message
  ver       kernel version
  mem       heap and memory info
  clear     clear screen
  halt      stop the cpu
```

跑完会 dump VGA 屏幕快照与统计：

```
  hlt 次数      : 0
  未映射访问    : 226
  中断开关      : 开
  串口字节数    : 953
```

**怎么进入交互**：默认脚本执行 `clear / help / ver / mem / bogus` 五条命令后退出。要跑自己的命令序列：

```sh
cat > /tmp/mycmds.txt <<'EOF'
clear
ver
mem
help
EOF
sh tools/run-emu.sh --script /tmp/mycmds.txt
```

`-q` 关闭串口实时回显，只打印最终快照。

**自动化验证**：

```sh
sh tools/test-kernel.sh     # 30 项断言
```

## 三、真镜像（QEMU 或真机）

### 3.1 构建

```sh
cd x-os
sh tools/build.sh
```

输出在 `C:/xtmp/xos-build/`（必须是纯 ASCII 路径，MinGW 的 `cc1` 在中文路径下建不出 `.o`）：

```
ok -> /c/xtmp/xos-build/xos.img
     boot sector : 512 字节
     kernel      : 71736 字节
     总计        : 72248 字节
```

构建过程六步，每步都有断言：

| 步 | 做什么 | 断言 |
|---|---|---|
| 1 | X 源码 → C | — |
| 2 | C → 目标文件（`-m32 -ffreestanding -nostdlib`） | — |
| 3 | 内核运行时 → 目标文件 | — |
| 4 | 引导扇区 + 入口桩汇编 | 扇区必须是 512 字节 |
| 5 | 链接（加载地址 0x10000） | **未解析符号必须为 0** |
| 6 | 导出裸二进制 + 拼镜像 | 段布局、值栈不压栈区、大小窗口 |

### 3.2 在 QEMU 里跑

```sh
# 有窗口（看 VGA 文本输出）
qemu-system-i386 -fda C:/xtmp/xos-build/xos.img

# 无窗口（看串口输出，适合 CI / 远程）
qemu-system-i386 -fda C:/xtmp/xos-build/xos.img -nographic
```

`-nographic` 下串口直连终端，中文正常显示。退出 QEMU 用 `Ctrl-A` 然后 `X`。

### 3.3 在真机上跑

镜像布局是「引导扇区 + 内核」，可当 1.44 MB 软盘写：

```sh
# 写 U 盘（⚠️ 确认盘符，写错会毁掉那块盘的数据）
# Windows：用 Rufus 选「DD 模式」写入 xos.img
# Linux/macOS：
dd if=C:/xtmp/xos-build/xos.img of=/dev/sdX bs=512 conv=fsync
```

BIOS 里设为 Legacy/CSM 启动（**不支持 UEFI**：引导扇区是 16 位实模式代码）。

## 四、内存地图（排错时先看这张表）

```
0x00400 - 0x004FF   BIOS 数据区（不碰）
0x04000             内核参数块（引导扇区写 magic "XOS1"）
0x05000             光标位置（无顶层可变变量，只能放固定地址）
0x10000             kernel.bin 加载起点
0x21840 起          .vstack 值栈 786 KB
0xE1840             .vstack 结束
0xF8000             内核栈底（栈向下最多用到这里）
0x100000            内核栈顶 = 堆起点（HEAP_START）
0x1000000           堆上限（HEAP_LIMIT，15 MB 可用）
0xB8000             VGA 文本缓冲（与上面重叠？见下）
```

> **0xB8000 落在 .vstack 范围内**（0x21840~0xE1840）。这是当前布局的一个真实问题：VGA 缓冲会被值栈覆盖。二进制值栈清零发生在 `_entry`（进 `main` 之前），而 VGA 首次写入在 `pm_entry` 清屏时（`_entry` 之前），所以顺序上侥幸不冲突；但只要值栈里出现借用的对象跨 VGA 写入……实际上**不会**，因为 VGA 是硬件地址，不被程序写。真问题在**内核栈**：早先栈顶设在 0x90000（落在值栈内），已修为 0x100000，并由 `build.sh` 的断言守住。

## 六、常见问题

**Q: 为什么 VGA 上的中文显示成 `?`**

VGA 文本模式每格只有 1 字节字形索引，指向卡上 256 个 CP437 字形，其中没有 CJK。内核按字形可用性降级成 `?`，而不是把码点截断（"中" 截断后是 `-`，会产出看似正常的乱字符，更难排查）。中文请走串口——那边是 UTF-8 字节流。

**Q: 内核启动后 CPU 占用 100%**

`shellLoop` 用忙等而不是 `hlt`，因为还没有 IDT 与时钟中断：`hlt` 之后没有任何中断能唤醒它。IDT 做完后换回 `hlt` 即可（`kernel/src/kmain.xle` 里 `shellLoop` 有注释说明）。

**Q: 改了 X 源码但构建没反应**

编译器 `build/x.exe` 是独立的可执行文件，改了 `src/codegen_c.c` 之后需要先重编编译器：

```sh
cd x-lang && sh tools/build.sh    # 重编 x.exe
cd x-os    && sh tools/build.sh    # 再构建内核
```

**Q: `kernel.bin` 变大到 800 KB 以上**

值栈落回了 `.data` 段。检查 `src/codegen_c.c` 里 `X_VALUE_STACK` 宏是否还在给裸机值栈加 `.vstack` 段属性。当前正常值 71,736 字节。

**Q: 构建报「无法写入 build/x.exe — 文件被占用」**

VS Code 的 LSP 进程（`x.exe lsp`）占着它。停掉：

```powershell
Get-Process x -ErrorAction SilentlyContinue | Stop-Process -Force
```

`tools/build.sh` 已内置 `mv` 回退，多数情况下无需手工介入。

**Q: `ld` 报 `section below image base`**

链接时漏了 `--image-base 0`。PE 默认镜像基址 0x400000，而内核段在 0x10000。
