# X 语言（工程名 x-lang）

> 一门面向**数据分析与服务端**两个主场的系统级语言：解释与 AOT 双档执行、强类型但零注解起步、内存全自动但可精确接管、原生支持中文编程。

- 短名：`X`（可执行文件 `x`；源文件后缀 `.xle`（英文）、`.xlc`（中文）；字节码 `.xbc`）
- 首个目标平台：Windows x86-64 → Linux x86-64 → macOS ARM64 → Linux ARM64
- 与 `x-os` 的关系：本语言是 x-os 的用户态首选语言，运行时设计刻意保持 freestanding（不依赖 libc），便于下沉到内核态

## 设计十一条铁律

这十一条是后续所有设计争论的裁决依据，冲突时按序号优先。

1. **无隐藏成本**。不做隐式深拷贝、不做热路径隐式分配。O(n) 的操作必须在源码里看得见（`clone()` / `.*` / `@`）。
2. **一份字节码，两档执行**。解释与 AOT 的输入是同一份寄存器式字节码，输出必须逐字节一致。不存在「只有编译模式才能用」的特性。
3. **强类型，零注解起步**。全局类型推断；注解只为人读、为跨模块稳定 ABI、为性能提示而写，不是编译器必需品。
4. **内存全自动，但可精确接管**。默认非原子 ARC + 逃逸分析；热点用 `arena`；系统级用 `unsafe` 手动块。三层可混用。
5. **数学是一等公民**。复数、N 维数组、矩阵运算符、广播、切片视图，全部进语言本体而非库。
6. **关键词可换语言，标识符永远 Unicode**。语言本体英文，中文编程是包，零运行时成本。
7. **一切可编译期求值**。`comptime` 是语言设施，用于泛型特化、矩阵常量折叠、DSL、代码生成。
8. **反射可裁剪**。运行时元数据按模块 opt-in，AOT 可完全剥离。
9. **单文件二进制，零运行时依赖**。`x build` 产出的可执行文件拷到同架构机器就能跑。
10. **工具链属于语言**。fmt / lint / doc / test / bench / pkg / LSP 全部内置，不做「社区自己解决」。
11. **错误必须可定位、可理解、可点击**。任何未捕获异常都要给出精确到列的源码位置、通俗的原因解释、可执行的修复建议，并支持一键跳转到出错行。

v0.4 新增的两条，放在铁律之外但同样具备裁决效力：

12. **一份核心，七档装配**（Profile）。运行时核心薄到能进内核（< 400 KB），其余能力按 `server` / `desktop` / `mobile` / `kernel` / `embedded` / `wasm` / `core` 七档裁剪。任何新特性必须说明它属于哪一档。
13. **所有权单位是并发域，不是线程**。域是一组协程加它们独占的对象图，同一时刻只在一个线程上运行，但可整域迁移。跨域共享必须显式标注。

v0.5 / v0.6 新增两条：

14. **每个名字自带它是什么**。引入目标永不写成字符串：包是 `@name`，模块是裸路径，标准库以 `std` 开头。任何一段代码被单独摘出来（日志、grep 结果、issue 片段）都必须还能读懂。**文件同理**：`.xle` 是英文源文件、`.xlc` 是中文源文件、`.xbc` 是字节码，看后缀就知道它是什么、该用哪套关键字。中文模式因此不依赖命令行开关，也就不存在「同一份代码换个终端就编不过」。
15. **别名是一等语法，且必须零成本**。`import X as Y` / `from X import a as b`，四种位置全部支持；`Y` 与 `X` 在符号表里是同一实体，生成代码逐字节一致。别名不是语法糖，是可读性工具——它一旦带来开销，用户就会在大循环里纠结，那时它从工具变成了陷阱。

**v0.12 新增**：数组、`for` 遍历、模块系统（`import`）、顶层 `const`、Win32 窗口运行时，以及用它写成的完整扫雷（`games/minesweeper/`，1 435 行 X 代码，解释与 AOT 两档截图**逐字节相同**）。

```
x run    <file.xle|.xlc|.xbc>    编译并执行，或直接执行字节码
x build  <file.xle|.xlc> [-o out] 编译为 .xbc 字节码
x build  <file> --emit=c  -o a.c  生成 C 代码（可拿到任何有 C 工具链的机器编译）
x build  <file> --emit=exe -o a.exe  编译成本机可执行文件
x build  <file> --emit=exe --target=x86_64-linux-gnu   交叉编译
x target list                    列出支持的目标三元组与产物格式
x disasm <file.xle|.xlc|.xbc>    打印反汇编
x check  <file.xle|.xlc>         只检查不执行
```

**打发行包**（拷到别的机器就能用，不需要 mingw / node）：

```
sh tools/release.sh              产出 release/xlang-<版本>/
sh tools/release.sh --zip        额外产出一个 .zip
```

布局是 `bin/`（`x.exe`）+ `lib/stdlib/` + `conf/` + `src/` + `docs/` + `tests/`，
脚本自带两项自检（能否执行、能否 `import std.math`），布局不对就当场失败。
目录顺序与查找规则见 [docs/打包与异地使用.md](docs/打包与异地使用.md) §五。

**调试编译器自身**（只在 `./tools/build.sh debug` 构建里有实质内容）：

```
X_TRACE=1 x.exe build foo.xle       打印编译流水线打点（带深度缩进）
X_CRASH=0 x.exe build foo.xle       关掉崩溃处理器，复现原始崩溃行为
./tools/where.sh 0x7ff6...          把崩溃地址反查成 源码:行:函数
```

崩溃处理器会报告异常码（`0xC0000005` 访问违例 / `0xC00000FD` 栈溢出）、出错模块名与模块内偏移、以及顺 `rbp` 链走的调用栈。没有它的话，「编译器崩了」和「源文件编译失败」在调用方看来都是非零退出码——本次定位扫雷的非确定性段错误时，正是靠它把范围从「整条流水线」缩到「`inject_pre_before_continues` 这一行」。

**可执行文件格式由操作系统决定，不是可选参数**：Windows 只能是 PE（`.exe`），Linux 只能是 ELF，macOS 只能是 Mach-O。所以参数是 `--target`（选平台）而不是 `--format`（选格式）——后者会允许构造出「格式对但跑不了」的产物。详见 [spec/02](spec/02-编译与运行时.md) §9.1.1。

**后缀即声明**：`.xle` 是英文源文件，`.xlc` 是中文源文件（自动开中文关键字模式，无需 `--zh`），编译产物是 `.xbc`。同一个程序存成哪种后缀，决定了关键字用哪套词，而字节码逐字节一致——中文零成本由后缀继承，不靠命令行开关保证。

P0 支持：`let`/`var`/`const`（含顶层 `const`，编译期字面量展开）、`fn`（含前向引用、递归、互递归）、`if`/`else`/`else if`、`while`/`loop`/`break`/`continue`、`for x in 0..n` 与 `for x in 数组`（纯语法糖，展开成 `while`）、数组（字面量 `[1, 2, 3]`、`array(n, fill)`、`[]` 读写、`len`）、三元 `cond ? a : b`、空值合并 `a ?? b`、可选链 `a?.b` / `a?[i]`、`match`（字面量/范围/绑定/守卫/通配/嵌套）、字符串插值 `"a{x}b"`、原始字符串 `r"a{x}b"`、算术/比较/逻辑/位运算（含 `<<`/`>>`/`&`/`|`/`^`）、字符串（拼接、比较、`len`、转义）、`print`/`println`/`toString`/`toInt`/`toFloat`/`abs`、块作用域、模块系统（`import "a.xle"` / `import name`，文本级合并）、29 个窗口内建（`winOpen`/`winFillRect`/`winText`/`winPollClick`，以及 `winFillRound`/`winGradient`/`winPushTransform`/`winAlpha`/`winClip`/`winTextRot` 等 12 个样式原语）、`.xlc` 中文关键字模式（后缀自动开启，`--zh` 作为 `.xle` 的冗余开关保留）。

**桌面程序：**

```x
// 一个最小窗口程序
fn main() -> Int {
    if !winOpen("Hello", 320, 200) { return 1 }
    var running = true
    while running {
        winBeginFrame()
        winFillRect(0, 0, 320, 200, 0x1E1E24)
        winText(20, 20, "你好，桌面", 0xE8E8F0)
        winEndFrame()
        if winShouldClose() { running = false }
        winSleep(16)          // ~60fps
    }
    winClose()
    return 0
}
```

即时模式：每帧从零重画，窗口系统不存任何状态，**状态只有一份**。29 个内建全是「画形状 / 画文字 / 读鼠标 / 取时间」以及形状与样式的变换，没有控件树也没有回调。完整用例见 `games/minesweeper/`，设计说明见 [spec/09](spec/09-桌面程序.md)。

**已实测的关键结论：**

| 结论 | 证据 |
|---|---|
| **一份字节码两档同结果** | 每个测试都跑 `x run a.xle` 与 `x build a.xle && x run a.xbc`，输出**逐字节一致**（全项通过） |
| **中文编程零成本** | `08-zh.xlc` 与 `08-zh-en.xle` 编出的 **125 条指令逐条一致**（超指令合并后；合并前 134 条同样逐条一致）；两份 `.xbc` 仅头部记录的源文件路径不同（文件名本来就不同），常量池与代码段完全相同 |
| **中文模式无需命令行开关** | `x run tests/p0/08-zh.xlc` 直接跑通，未传 `--zh`；`--zh` 缺失不影响任何结果 |
| **类型化字节码有效** | 整数循环 3000 万次是 C `-O0` 的 **5.5×**（6 对超指令生效后，关闭时为 11.0×）；fib(33) 是 8.0× |
| **超指令只改速度不改语义** | 每个测试都用 `X_NO_SUPER=1` 再跑一遍，输出**逐字节相同**；实测收益 **1.66×**（循环）/ 1.36×（递归），循环体从 12 条字节码压到 7 条 |
| **已超 CPython** | 同机同任务，循环 820ms vs CPython 约 3500ms |
| **AOT 与解释器逐字节一致** | 每个测试都额外用 `--emit=exe` 编译并运行产物，与解释档输出**逐字节相同**（全项通过）。这条检查抓到过一整类「不崩溃、不报错、只是算成 0」的下标错误 |
| **AOT 快 1.46×** | 3000 万次循环：解释器 447ms → AOT 300ms（C `-O0` 100ms / `-O2` 63ms）。**上限是模型决定的，不是实现质量**：手写同等 `V` 结构的纯 C 循环也要 111ms，见 [spec/07](spec/07-高性能解释器.md) §3.9.2 |
| **平台边界隔离** | `tools/check_portable.sh` 5 项：除 `platform.c/h` 外零 `_WIN32`/`__APPLE__`/`__linux__`，零 `<windows.h>`/`<unistd.h>` 泄漏，19 个编译单元零警告 |
| **C -O2 在串行循环上无加速** | 3000 万次循环：C `-O0` 120ms / `-O2` 105ms。gcc 的加速主要靠向量化，带 `%` 的真串行依赖链无法向量化——所以「追平 -O0」与「追平 -O2」在这个基准上难度接近 |
| **溢出必须 trap** | 按 01 §5.4 实现（`__builtin_*_overflow`），`maxv + 1` 精确报出 `18:16` 并给修复建议 |
| **诊断六段式** | 编译期 18/18 场景带 `help` 段（覆盖率 100%），运行时 13/13 带 `note`+`help`，位置全部精确到列 |
| **UTF-8 端到端正确** | `tools/check_utf8.sh` 11 项：输出字节合法 UTF-8、BOM 剥离、**列号按字符计**（`2:13` 而非字节的 `2:23`）、GBK 文件明确报编码错、中文路径可读写含 `.xbc`、诊断标签按显示宽度对齐、纯 ASCII 不受影响 |
| **Windows 终端不乱码** | 启动设 `CP_UTF8` 并在 `atexit` 还原，父 shell 代码页不被污染；输出重定向到文件时字节仍是 UTF-8 |
| **无内存泄漏** | 50 万次字符串拼接，峰值 RSS 12.8 MB（若漏释放应累计约 125 GB） |
| **桌面程序两档一致** | 扫雷的 `demo.xle` 用固定种子造四个局面各截一张图，解释器与 AOT 产物生成的 BMP **四张全部逐字节相同** |
| **AOT 产物自包含** | `--emit=exe` 产物内含窗口运行时源码（`Microsoft YaHei` 以 UTF-16 出现 2 次），只依赖系统 `GDI32.dll`/`USER32.dll`；不用窗口的程序不内嵌、不链这两个库 |
| **中文窗口标题无乱码** | 全部 Win32 调用走 `W` 系列 API（`TextOutW`/`CreateWindowW`/`_wfopen`），UTF-8→UTF-16 显式转换；中文系统 CP936 下不乱码 |
| **标准库是「文件」，不是「链接」** | 9 个模块（`math` / `json` / `str` / `array` / `conv` / `ui` / `fs` / `http` / `db`）全是 `.xle` 源码，按**可执行文件所在目录**查找，与 cwd 无关。`x.exe` + `stdlib/` 拷到任意目录，`import std.fs` 直接可用（三种场景实测） |
| **包管理闭环** | 声明 → `import @name` → 解析 → 编译 → 运行，四档全部一致。未声明的 `@name` 报错位置指向那句 import（不是清单）；依赖源码缺失时列出试过的每条路径 |
| **包管理有版本维度** | 本地注册表 `packages/包名/版本/`，语义化约束（`^ ~ = >= <= *`）、传递依赖、冲突时报出双方来源。`x.lock` 冻结版本：`install` 不自动升级、`update` 才升、`pkg lock` 给 CI 用的退出码。66 条 semver 断言 + 8 项端到端 |
| **注册表也是「文件」** | 注册表就是目录约定（`packages/包名/版本/src/lib.xle`），用户可手工往里放包，不需要任何命令参与。默认在 `x.exe` 旁边，可用 `X_REGISTRY` 改 |

性能基线的完整测量方法与解读见 [tests/p0/12-perf.xle](tests/p0/12-perf.xle) 文件头。

**P0 的已知限制（P1 偿还）：**

- 无泛型、无闭包、无 `super` 调用（`super(...)` 在构造链里报「期望一个表达式」）；
  结构体与类**已实现**（见下面「类系统」一段）
- 无 `defer`（给 warn + note + help，不静默忽略）
- `match` 已实现字面量/范围/绑定/守卫/通配/嵌套；**未实现**结构体与枚举解构、
  `|` 或模式（需要先有 enum 类型）
- 字符串插值已实现 `{expr}`、`{{`/`}}`/`\{` 转义，以及**花括号自动退回字面量**
  （`"{}"` / `"{\"a\":1}"` / `"a{b"` 都原样输出，见 [01](spec/01-语言设计.md) §3.6.1）；
  原始字符串 `r"..."`（不转义、不插值，§3.6.2）；**未实现** `{expr:spec}` 格式说明符
  与三引号多行字符串
- 无异常捕获（`try`/`catch`）；运行时错误直达进程退出
- 模块系统是**文本级合并**：无命名空间、无导出表、无独立编译、无符号表（`from X import a, b` 只解析不使用）
- 顶层 `const` 必须是字面量，不做常量表达式折叠（`const A = B + 1` 报错，`comptime` 排在 P1）
- 类型推断只分 Int/Float/Bool/String/Array，不做结构化推断
- 整数溢出检查已生效，但 `+%`/`+|`/`+?` 三个显式语义算子未实现
- 字符串拼接是 O(n²)（每次 `+` 重新分配整串），P1 需引入 rope 或 builder
- 无 `break` 带标签、无循环 `else`、无 `while` + `for` 之外的迭代形式
- 窗口只支持 Windows；Linux/macOS 是空实现（能编译、能跑逻辑、画不出东西）
- 无图片加载、无 alpha 混合、无抗锯齿线条、无多窗口、无键盘输入、无文字换行

**类系统（v0.15–v0.16）的现状与取舍：**

| 能力 | 状态 | 说明 |
|---|---|---|
| `class` / `interface` / `abstract` / `final` | 已实现 | 单继承 + 多接口；抽象类不可实例化 |
| 字段与方法 | 已实现 | 字段类型必填（要定偏移）；构造函数不继承、不进虚表 |
| 虚方法派发 | 已实现 | 全局方法槽 + 每类虚表，槽号编译期确定（见 [02](spec/02-编译与运行时.md)） |
| `private` / `protected` / `public` | 已实现 | **字段与方法都检查**；`public` 与 `pub` 等价 |
| 覆写不收窄可见性 | 已实现 | 父类 public → 子类 private 编译期拒绝（LSP 直接推论） |
| 反射 | 已实现 | `className` / `classParent` / `classIs` / `classFields` / `classMethods` / `fieldGet` / `fieldSet` / `fieldHas` / `methodHas` |
| 注解 | 已实现 | `@Name` / `@Name(args)` / `@Name(k = v)`，可标在类、字段、方法上；运行时用 `annoHas` / `annoGet` / `annoGetKV` / `annoAll` 查询 |
| `super(...)` 构造链 | **未实现** | 子类构造函数要自己初始化父类字段；`super.method()` 同样不可用 |

**反射与注解的三个边界，值得提前知道：**

- **反射守可见性，不绕过它**。`fieldGet(obj, "secret")` 读 private 字段会在运行时被拒 —— 判据与编译期完全一致（本类 / 子类 / 全开）。反射是「运行时按名字访问」，不是「无视访问控制」。类外读 private 有专门的负例测试 `tests/p0/40-reflect-private-deny.xle`。
- **注解不继承**。字段/方法的注解是**声明点**的属性，子类没重新标注就是没有 —— 与 `@Deprecated` 的语义一致（父类旧方法废弃不代表子类重写的方法也废弃）。框架要继承语义，自己沿 `classParent` 走。
- **注解实参只收字面量**（Int / Float / String / Bool / null）。注解在编译期就变成元数据、还要能单独写进 `.xbc` 发给没有源码的机器；支持 `@Size(n * 2)` 需要编译期求值，那是 comptime 能力，P1 才有。写表达式会得到一条说清原因的错误，而不是悄悄存一个求值不了的 AST。
- **AOT 侧的 `fieldGet` / `fieldSet` 不做访问控制**。编译器在编译期已拒绝直接访问 private 字段，绕过的唯一路径是显式调用反射 —— 那是一个用户主动写的动作。收紧的做法是给生成的 `xf_N` 加一个类索引参数（解释器侧的 `Frame.cls_idx` 已经把语义定下来了），留待需要时做。这个差异需要明确记录，不能假装不存在。

**标准库与包管理当前的边界（不只是「没做」，还有「为什么现在不做」）：**

- 标准库 9 个模块全部是 `.xle` 源码，在 `run` 与 AOT 两档下都能用；但它们是**解释执行的源码**，没有预编译缓存，大型项目首次编译会明显变慢
- `std.http` 服务端是**单轮调度**（`httpPump` 处理一轮请求），不是线程池；并发能力取决于有多少次 `httpPump`，没有内建的多路复用
- `std.http` 客户端只做明文 HTTP。**没有 TLS** —— 所以它不能用来下载包，也不该被当成访问外部 HTTPS 服务的手段
- `std.db` 是**表文件 + 单列索引**，不是关系数据库：没有 JOIN、没有多列索引、没有并发写保护。事务是「内存快照 + 提交时整表重写」，数据量上去之后提交会变慢
- 包管理是**本地注册表**：没有下载、没有签名、没有审计。注册表就是目录约定，谁往里放东西谁负责
- 依赖解析用「最高可用版本 + lock 冻结」，不是规范里裁决的 MVS（取最高下界）。差别只在**没有 lock 时第一次挑哪个**；接远程注册中心时换掉 `pick_version` 的策略即可，其余逻辑不动。记录在 [spec/03](spec/03-标准库与包管理.md) §6.4.0
- `x.lock` 没有 `source` / `checksum`：那两个字段的意义完全依赖「网络取到的字节需要校验」，本地目录没有这个前提。写一个假校验和比不写更糟 —— 它看起来像被验证过
